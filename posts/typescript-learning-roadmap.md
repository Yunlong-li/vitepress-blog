# TypeScript 学习路线（有 JS 基础）

你有 JS 基础，学 TS 的关键不是“语法记忆”，而是建立**类型建模思维**。

一句话：**用类型提前暴露错误，用约束提升协作效率。**

---

## 1. 第一阶段：补齐 TS 核心语法

### 1.1 基础类型与函数类型

重点掌握：

- `string` / `number` / `boolean` / `null` / `undefined`
- 数组、元组、对象类型
- 函数参数与返回值标注
- 可选参数、默认参数、剩余参数

### 1.2 联合类型与类型守卫

这是 JS 开发者转 TS 的第一道坎：

- `A | B`
- `typeof` / `in` / `instanceof`
- 自定义 type predicate

目标：让你在分支里拿到准确类型，而不是到处 `as any`。

### 1.3 interface 与 type

你要知道：

- `interface` 适合对象形状扩展
- `type` 更适合联合、映射、工具组合
- 实际项目中两者并存，核心是可读性与一致性

---

## 2. 第二阶段：学会“类型建模”

### 2.1 泛型

高频场景：

- 通用 API 响应体：`ApiResponse<T>`
- 列表分页：`PageResult<T>`
- 工具函数复用

### 2.2 keyof / typeof / indexed access

这套组合很重要：

- 从值反推类型
- 从对象 key 推导 value 类型
- 避免字符串硬编码

### 2.3 映射类型与条件类型

至少理解并会用：

- `Partial<T>`、`Required<T>`、`Pick<T, K>`、`Omit<T, K>`
- `Record<K, V>`
- 条件类型 `T extends U ? X : Y`

这部分会直接提升你对大型项目类型声明的阅读能力。

---

## 3. 第三阶段：工程化落地

### 3.1 tsconfig 关键配置

建议重点理解：

- `strict`
- `noImplicitAny`
- `strictNullChecks`
- `paths` 与 `baseUrl`

建议：新项目尽量开启严格模式，老项目渐进迁移。

### 3.2 与前后端生态配合

- 前端：Vue/React 组件 Props 类型、Hooks 类型
- 后端：DTO、接口返回类型、中间件上下文类型
- 全栈：前后端共享类型（谨慎控制耦合）

### 3.3 类型规范

团队中建议约定：

- 禁止滥用 `any`
- 优先 `unknown` + 缩小
- `as` 断言必须有理由
- 公共类型集中管理

---

## 4. TS 学习中的典型误区

1. **把 TS 当成“加注释”**：没有做约束设计。
2. **遇错就 `as any`**：失去类型系统价值。
3. **过度炫技类型体操**：可读性下降，维护困难。
4. **只会写不会读**：看不懂第三方库 d.ts。

## 5. 建议实战项目

### 项目 A：把现有 JS 工具库迁移到 TS

目标：练接口定义、泛型、工具类型。

### 项目 B：实现一个请求 SDK

包含：

- 请求/响应泛型
- 错误类型归一
- 拦截器类型约束

目标：练习复杂类型组织。

### 项目 C：中型业务模块重构

- 状态管理类型化
- 表单模型类型化
- 接口数据到视图模型转换

目标：把类型系统真正用于业务治理。

## 6. 4 周学习安排

- 第 1 周：基础语法 + 联合类型 + 守卫
- 第 2 周：泛型 + 工具类型 + 类型推导
- 第 3 周：tsconfig + 项目迁移实践
- 第 4 周：阅读第三方类型声明 + 重构沉淀
